# ESPHome 2026.10

Reviewed up to: 2026.10.2 (2026-11-06)
Sources: https://esphome.io/changelog/2026.10.0/,
https://esphome.io/blog/2026/10/21/esphome-2026-10/

## Breaking changes (YAML)

- light: `restore_mode` is deprecated in favour of `restore_state` (#18997).
  Mappings: `RESTORE_DEFAULT_OFF` → `restore_state: all`;
  `RESTORE_DEFAULT_ON` → `initial_state: {state: ON}` plus
  `restore_state: all`; `RESTORE_INVERTED_DEFAULT_OFF` →
  `restore_state: {state: INVERT}`; `RESTORE_AND_OFF` →
  `restore_state: {state: OFF}`; `ALWAYS_OFF` → set neither key. A light with
  `initial_state: {state: on}` and no `restore_mode` now boots on (it was
  forced off before). A light with neither key and no `initial_state` still
  boots off.
- speaker media player: `codec_support_enabled` removed (#19074); set the
  pipeline `format: NONE` for the old behaviour.
- speaker, speaker_source: volume and mute are independent (#19307, #18412);
  volume zero no longer fires `on_mute`/`on_unmute`.
- climate_ir: heat/cool auto mode only when both heat and cool are supported
  (#19483); add `supports_heat_cool: true` to keep it.
- remote_receiver: RMT ring buffer sized from receive symbols (#19100);
  `buffer_size` is bytes on ESP8266, RP2040, LibreTiny, ESP32-C2 and
  ESP32-C61 (#19101), so multiply explicit values by 4.
- esp8266: native Arduino toolchain is the default (#19886); first build is
  clean; `toolchain: platformio` is deprecated (removal 2027.4.0).
- host: native ninja build (#19214); unsupported `platformio_options` keys
  rejected; Windows host builds unsupported.
- sendspin: switch platform requires `type` (#20189); needs Music Assistant
  2.10.7 / 2.11.0b4; ESP32 framework must be `esp-idf`.
- usb_host / usb_uart: overlapping VID/PID entries rejected; split with
  `manufacturer` / `product` filters (#19095).
- epaper_spi: monochrome conversion changes for saturated colours;
  `full_update_every` > 1 rejected without partial refresh;
  `seeed-reterminal-sticky` needs `psram` (#19213).
- homeassistant.action: maps with more than 255 keys rejected.
- hoermann_hcp: commands sent once; lamp handled as a state (#19765).
- nfc: lambdas modifying `tag` in `on_tag`/`on_tag_removed` now modify the
  shared reference.

## Behaviour changes

- esp32: recommended ESP-IDF 5.5.6 (#20987); builds call cmake/ninja
  directly instead of `idf.py`.
- esp32: mbedTLS trimmed to client defaults, disabled entirely when no
  component needs crypto (#19088, #18877).
- light: `resume_effect`, `transition_state_publish_interval` (>= 150 ms),
  colour names and `0xRRGGBB` in light states.
- esp32_ble_tracker: guards Bluedroid against stale connection requests
  (#19375); actions moved to apply helpers, YAML unchanged.
- logger: ESP8266 log strings stay in flash; RAM option deprecated (#19577).
- ota: compressed uploads on ESP32, RP2040, LibreTiny and host (#19037);
  new `allow_plaintext_upload` (#19396).
- api: new `outgoing_connection` (requires `encryption`) and device wizard.

## C++ API changes (lambdas and external components)

- select: options are a flash `ConstVector` (#20117); code that used the old
  option vector does not compile. `active_index()` is not listed as changed.
- light: `LightState` reorganised (180 → 168 bytes, #19711); restore
  pipeline built by generated lambdas, so subclasses that reached into it
  must change. `LightCall::set_effect` gained a `StringRef` overload
  (2026.10.1).
- core: `Action::stop_complex` and `Action::is_running` are no longer
  virtual; drop `override`. `APIServer` and `WebServer` dropped the
  `Controller` base class.
- api: `HomeAssistantServiceCallAction` setters removed; use
  `CustomAPIDevice::call_homeassistant_service()`. Protobuf encode/decode
  virtuals merged.
- sensor: `Sensor::raw_state` removed; use `get_raw_state()`.
- template: `bypass_before_arming()` removed.
- remote_base: `encode`/`decode`/`dump` no longer virtual; register
  listeners and dumpers from `to_code()`.
- climate_ir: mode booleans replaced by `ClimateModeMask modes_`.
- Also changed: `audio_file` pointers are const; `NdefMessage::get_records()`
  returns `unique_ptr` elements; `http_request` setters take `const char *`;
  `modbus_controller` shims moved to `modbus::helpers`;
  `Nextion::get_wave_chan_id()` removed.

## Patch releases

### 2026.10.1 (2026-10-27)

- Generated lambda code is emitted after user includes; custom code relying
  on include order may change.
- ESP32 BLE ignores unhandled key GAP events.
- LEDC resets through the HAL on targets without the legacy peripheral API.
- Precompiled header disabled on ccache older than 4.7.

### 2026.10.2 (2026-11-03)

- bluetooth_proxy releases held connections when a new client replaces the
  subscriber.
- TLS 1.3 kept working for `audio_http` on ESP32.
- LibreTiny OTA workaround prevents bricking RTL8710B on compressed updates.

## Gaps

- The sources list no YAML breakage for esp32_ble, esp32_ble_tracker,
  bluetooth_proxy, wifi, api, globals, script, or esp32_rmt_led_strip.
- Exact C++ signatures are not given; `config` does not compile lambdas, so
  lambda compatibility is unverified until a compile.
